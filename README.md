# Сайт ансамбля «Степь»

Статика: HTML + CSS + ванильный JS, без сборки и фреймворков. Весь изменяемый
контент вынесен в JSON-файлы в `content/` и подгружается на страницах через
`js/content.js`. Управлять этим контентом можно либо руками (редактируя JSON),
либо через панель `/admin/` (Decap CMS) — это и есть решение «без кода» для
участников ансамбля.

## Структура

```
index.html, about.html, video.html, achievements.html,
announcements.html, contacts.html   — страницы
css/style.css                       — все стили
js/content.js                       — подгрузка content/*.json на страницы
js/main.js                          — анимации появления секций и параллакс
content/*.json                      — редактируемый контент (тексты, списки, ссылки)
images/                             — картинки; images/uploads — сюда CMS кладёт загруженные фото
admin/index.html, admin/config.yml  — панель управления (Decap CMS)
```

Лого сейчас — `images/logo-placeholder.svg`, простая замена текста мокапа.
Когда появится финальный логотип — либо перезалить SVG/PNG под тем же именем,
либо загрузить новую картинку через админку (поле «Картинка лого» в разделе
«Главная страница» — оно перекрывает текстовый вариант).

## 1. Публикация на GitHub Pages

```bash
cd steppe-website
git init
git add .
git commit -m "Первая версия сайта"
git branch -M main
git remote add origin https://github.com/ВАШ_АККАУНТ/НАЗВАНИЕ_РЕПО.git
git push -u origin main
```

Дальше в репозитории: **Settings → Pages → Source: Deploy from a branch →
Branch: main / (root)**. Через минуту сайт будет доступен по адресу
`https://ВАШ_АККАУНТ.github.io/НАЗВАНИЕ_РЕПО/`.

## 2. Панель управления для ансамбля (Decap CMS)

Панель уже лежит в `admin/`, но ей нужен способ входа через GitHub. Так как
GitHub Pages — это просто статика без сервера, аутентификацию делает
бесплатный сервис-прослойка. Самый простой вариант — Netlify (сам сайт при
этом **продолжает жить на GitHub Pages**, Netlify нужен только для кнопки
«Войти»):

1. Зарегистрируйтесь на [netlify.com](https://netlify.com) (можно через GitHub).
2. **Add new site → Import an existing project** и укажите тот же
   GitHub-репозиторий. Build command и publish directory можно оставить
   пустыми/по умолчанию — этот Netlify-сайт используется только как «прокладка»
   для логина, не как основной хостинг.
3. В настройках этого Netlify-сайта: **Site configuration → Identity → Enable
   Identity**, затем **Services → Git Gateway → Enable Git Gateway** —
   либо, если используете именно GitHub OAuth (как настроено в `config.yml`
   этого проекта), включите **Site configuration → Access control → OAuth →
   Install provider → GitHub** и укажите там Client ID/Secret из GitHub OAuth
   App (создаётся в GitHub: **Settings → Developer settings → OAuth Apps**,
   Authorization callback URL: `https://api.netlify.com/auth/done`).
4. В `admin/config.yml` замените `repo: OWNER/REPO` на реальные
   `имя_пользователя/название-репозитория`.
5. Откройте `https://ВАШ_АККАУНТ.github.io/НАЗВАНИЕ_РЕПО/admin/` — появится
   кнопка «Login with GitHub». Участникам ансамбля для входа нужен будет
   собственный GitHub-аккаунт (можно сделать бесплатно за минуту) и доступ
   к репозиторию (добавить их как Collaborators в настройках репозитория).

После входа в `/admin/` открывается обычная админка с понятными разделами
(«Главная страница», «О нас», «Достижения» и т.д.) — поля, загрузка фото и
кнопка «Publish», без единой строки кода. Каждое сохранение делает коммит в
репозиторий, сайт на GitHub Pages обновляется автоматически в течение
минуты-двух.

> Если позже сайт переедет на «настоящий» хостинг — этот шаг с Netlify-логином
> всё равно можно оставить как есть: он отвечает только за вход в панель,
> сам сайт как отдавался статикой, так и будет отдаваться.
